# 卡比的一筆冒險

卡比主題復古掌機風的一筆畫網頁遊戲。目標是兼顧幾何美感、路線推理與循序學習，以 **8 章、每章 25 關，共 200 關**構成完整體驗。

> 本 README 同時記錄需求與目前實作，更新日期為 2026 年 10 月 30 日。本次改版已實作 8 章、200 關與下列 10 種機制；原始碼、題庫、生成器與驗證腳本一併同步。自動驗證涵蓋解法與操作規則，關卡趣味與難度仍可依試玩調整。

[改版 Demo](https://kirby-pocket-line-demo.abloompony7.chatgpt.site)（已公開，可直接開啟遊玩與分享；實際功能以部署版本為準）

## 1 產品目標

玩家應該因為看懂圖形、想通路線和掌握機關而獲得成就感。難度來自有意義的選擇、先後順序與規則組合，不以增加節點、拉長線段、堆疊折角或降低觸控容錯製造困難。

前期使用三角形、正方形、長方形、菱形等基礎幾何；後期善用星芒、花窗、蜂巢、寶石切面和交織紋樣。200 關應有節奏地使用簡潔與複雜圖形，不要求每關都使用複雜造型。

## 2 已確認的核心需求

- 總計 200 關，8 章，每章 25 關。
- 第一章從易到難；第二章起提高推理要求，同時讓每個新機制有獨立的學習空間。
- 章節採**漸進引入、逐步組合**，不限制一章只能新增一個機制。同章可分階段引入兩個輕量機制，但不可在同一教學關突然一起出現。
- START 與紅線的第一、二章安排只是說明教學節奏的例子，並未定案；本次實作的具體分配見第 5 節，屬可依試玩調整的開發安排。
- 以將 10 個機制納入 8 章為規劃方向，可在第一、二章各安排兩個適合前期的機制，其餘章節各安排一個；具體分配依教學負擔與試玩調整。
- 保留路線提示、撤回、音效、振動開關與本機進度保存。
- 全介面使用繁體中文，採卡比主題掌機外觀與柔和配色。
- 線條加粗、圓點和整個連線圖案放大，適合手機操作。
- 移除冗長的首頁操作說明；新機制出現時保留必要的短句、圖示與操作回饋。
- 不在本次範圍加入帳號、共享排行榜或跨裝置同步。

## 3 基本操作與完成規則

1. 按住允許的起點，沿已有線段連續拖曳。
2. 普通線段走一次；圓點可以重訪。特殊線段依其規則完成。
3. 中途鬆手會重置本次路線；已通關時，鬆手不得清除結果。
4. 支援原路回拖撤回，以及 B 按鈕、Z／Backspace 撤回。
5. 普通線或已完成雙程要求的線，原路回拖可撤回；紅線尚欠第二次經過時，立即沿紅線折返算第二次通過。需要取消該步時使用 B 或鍵盤撤回，畫面須有簡短說明。
6. 撤回必須恢復線段次數、當前位置、機關方向、鑰匙及其他狀態，不能只清除顏色。
7. 圖形外觀應具有完整、清楚的封閉輪廓，避免無意義的懸空枝條。**圖形閉合不等於完成路線必須回到起點**，不可擅自要求所有關卡都能任意起筆、繞回原點。
8. START、方向、次數與其他關卡條件全部滿足後才算通關。

## 4 十個遊戲機制

本次實作涵蓋以下 10 個機制。前兩章各分階段引入兩個機制，後六章各引入一個；具體關卡見第 5 節。

| 編號 | 機制 | 規則與推理重點 |
| --- | --- | --- |
| 1 | 指定 START 點 | 必須從標示的圓點起筆，從固定位置安排路線。 |
| 2 | 紅線雙程 | 紅線必須經過兩次，普通線一次，安排回程與區域進出。 |
| 3 | 單向箭頭 | 指定線段只能順箭頭方向通過，決定進入方向與繞行順序。 |
| 4 | 方向翻轉點 | 每次到達綠點，指定綠色箭頭反向，控制觸發時機與次數。 |
| 5 | 成對傳送門 | 到達入口後，立即從配對出口繼續畫，連接不同區域。 |
| 6 | 順序檢查點 | 第一次到達檢查點必須依 A→B→C 順序；普通節點仍可重訪。 |
| 7 | 鑰匙與鎖線 | 取得鑰匙後才開放對應線段，先取得通路再安排後續路線。 |
| 8 | 雙色切換 | 紅／藍通道隨切換點輪流開放，在正確狀態下進入路段。 |
| 9 | 立交橋 | 有明確橋拱標記的交叉線不連通，不能在交叉處轉彎。 |
| 10 | 單次轉向機關 | 第一次到達時讓指定線段反向，之後保持不變，安排唯一觸發時機。 |

### 特殊規則細節

- START 點必須明顯顯示「S」或「START」。從錯誤圓點按下時不得開始路線，需提示正確起點。
- 紅線須同時以顏色與「×2／1/2／2/2」標示，不只依靠顏色辨識。
- 單向線須有清晰箭頭；逆向不得計入通過，不能自動吸附到另一條合法線掩蓋操作結果。
- 回拖撤回屬取消操作，不能被單向限制擋住。
- 綠點以「到達」觸發一次，停留或抖動不得連續觸發；從綠點起筆不觸發。撤回該次到達須還原方向。
- 傳送門：到達 P 立即移至配對出口，不連鎖傳送；保持按住，將手指移到出口後續畫。移動到出口期間不計入線段；B 可撤銷整次傳送與到達效果。從 P 起筆不傳送。出口到達亦依相同機關規則處理。
- 檢查點：首次到達依 A→B→C；已到達者可重訪，從 A 起筆視為已到達 A，不允許從 B／C 跳過順序。
- 鑰匙：到達或從 K 起筆會取得，重訪不重複取得；K ▣ 鎖線須持有 K 才能通過，虛線代表尚未開鎖。
- 雙色通道：初始為 R；每次到達 ◐ 切換 R／B，起筆不切換。只有當前色可通過；R／B 字母與實線／虛線共同標示。
- 單次機關：首次到達 ① 令金色箭頭反向，其後重訪不再觸發，起筆不觸發。
- 每一步保留完整狀態快照。回拖、B、Z／Backspace 均恢復到該步之前；鬆手、重新起筆及換關會清除本次機關狀態。機關採立即切換，不設需等待的動畫鎖。
- 未使用立交橋機制前，所有線段交叉都必須有可連通的圓點；不可讓玩家猜測交叉處是否相通。

## 5 章節規劃與教學節奏

以下是本次實作選擇的章節配置，並非把使用者先前的舉例當作固定安排。後續可依實際試玩調整，保持 8 章、200 關和逐步教學。

| 章節 | 關卡 | 新機制與首次教學 | 後續節奏 |
| --- | --- | --- | --- |
| 第一章・草原星球 | 1–25 | 1–8 基礎操作；9 START；16 單向箭頭 | 9–15 練習 START；16–20 單獨練箭頭；21–25 結合 |
| 第二章・奶油雲海 | 26–50 | 26 紅線雙程；36 立交橋 | 26–30 單獨紅線；31–35 結合 START；36–40 單獨橋；41–50 再組合 |
| 第三章・糖果森林 | 51–75 | 51 方向翻轉 | 51–55 單獨認識；之後逐步結合 START、箭頭、紅線 |
| 第四章・月光湖畔 | 76–100 | 76 成對傳送門 | 先從兩個三角形學傳送，再使用不同幾何區域與舊規則 |
| 第五章・冰晶王國 | 101–125 | 101 順序檢查點 | 前 5 關單獨練習，再安排順序與方向／回程的取捨 |
| 第六章・星砂沙漠 | 126–150 | 126 鑰匙與鎖線 | 前 5 關練習先取鑰匙，再逐步組合舊規則 |
| 第七章・夢境銀河 | 151–175 | 151 雙色切換 | 前 5 關認識 R／B 與切換點，再加入方向、順序等限制 |
| 第八章・願望之星 | 176–200 | 176 單次轉向 | 前 5 關認識唯一觸發，再與已學機制形成綜合挑戰 |

後六章的前 5 關保留新機制的獨立練習；之後選擇性加入已學規則，避免每關堆滿全部機制。題庫以穩定 ID、章節、教學階段和機制清單記錄每關配置。

### 每個新機制的引入流程

1. **單獨認識**：以熟悉的小圖形展示新規則，短句說清操作與回饋。
2. **獨立練習**：改變位置與路線，確認玩家理解規則，而非記住同一個答案。
3. **結合舊規則**：先與一個已學機制結合，再逐步增加組合。
4. **階段挑戰**：設計有路線取捨的關卡，並安排短關或複習關調節節奏。

同一章引入兩個機制時，先完成機制 A 的教學與鞏固，再單獨介紹 B，最後才讓 A、B 逐步結合。不能把「同章可教兩個」理解為「章首一次塞兩個」。

### 第一章的難度要求

- 初段使用三角形、正方形、長方形、菱形、梯形與多邊形，學習連線、鬆手重置及撤回。
- 後續才加入小屋、信封、蝴蝶結等小型組合，並分階段介紹本章選定的新機制。
- 可以安排兩個輕量機制，但基礎操作與練習空間不可被壓縮。
- 不因為要放入 10 個機制，就在第一章使用密集花窗、複雜狀態或多項規則同時出現。

### 第二章以後的難度要求

提高的是路線判斷與機關運用，不是讓每個圖都變複雜。新機制的教學關可以暫時降低圖形複雜度；熟悉後再提高組合難度。各章應穿插短關、精簡造型與複習關，避免疲勞。

## 6 幾何設計與美感

### 基礎與進階造型都要善用

- 基礎：三角形、正方形、長方形、菱形、梯形、多邊形。
- 組合：小屋、信封、蝴蝶結、雙菱形、簡單花窗。
- 進階：五芒星切面、六芒結晶、八角花窗、玫瑰窗、蜂巢、立方體、鑽石切面、交織三角、風花、星環與冠冕。
- 重視對稱、比例、節奏、留白與辨識度。不是將所有基礎圖形替換成複雜花紋。

### 每個節點都要有用途

圓點應用於輪廓轉角、真實分岔、必要交會或機關。直線上的無功能中繼點必須移除，不得把一條直線切成多段來增加數字。不得以無意義折返、冗長走廊或附掛小圈湊關卡。

### 變體必須有實際意義

可以重用優質輪廓，但新配置應改變起點選擇、進出順序、回程或機關時機。單純旋轉、鏡像、拉長或加節點不能充當新難度。不同輪廓與變體應穿插出現，避免連續重複。

### 手機可讀性

第一章原則上控制在約 7 個節點、12 條線段以內；這是可讀性護欄，不是湊滿目標。密集星窗與花紋放在後期，仍需檢查節點間距、箭頭、次數標示與手指遮擋。

長線不得穿過未連通的圓點，不得藏有重疊短線。除非明確採立交橋規則，交叉線需拆成真實節點。不得以降低吸附、縮小目標或增加誤觸製造難度。

## 7 介面與回饋

- 卡比主題掌機涵蓋機殼、按鈕、螢幕、選關與通關畫面，搭配柔和粉色、奶油白和星星／像素元素。
- 裝飾不遮擋線段、節點與操作按鈕。
- 選關顯示章節、新機制、解鎖與完成狀態。
- 進度統計依線段需要經過的總次數計算；例如三角形中一條紅線需走兩次，總進度是 4 次。
- START、紅線、箭頭、機關點與其他特殊狀態有文字或形狀輔助。
- 音效採輕快復古方向，避免高頻連線音刺耳；聲音與振動可關閉並保存設定。
- 錯誤操作提示原因，例如「請從 START 出發」「這條線只能順箭頭走」，不把規則失敗混成一般觸控失靈。

## 8 提示與關卡資料

每關資料需明確記錄：圖形名稱、節點與連線、章節、教學階段、START、經過次數、方向、機關對象及其他使用中的限制。

提示必須遵守全部當前規則，不能播放忽略紅線、START 或翻轉狀態的普通路徑。可儲存預先驗證的完整解法以避免手機卡頓，但使用前仍需檢查解法與題目資料一致。

生成器不能為了讓圖有解，自動偷偷加入玩家尚未學過的紅線或其他機關；應重新設計路線。

## 9 存檔與相容性

保留目前瀏覽器的解鎖進度、完成紀錄與設定。改動題庫時使用穩定關卡識別，避免錯套題目或無提示清空進度。需要轉換時先備份舊紀錄並提供清楚說明。

本機保存不代表已具備登入、雲端存檔或跨裝置同步。

## 10 驗收條件

1. 正確顯示 8 章、每章 25 關，共 200 關。
2. 完整規劃涵蓋 10 個機制；章節可分階段引入多於一個機制，具體分配需明確記錄，不把先前舉例誤當定案。
3. 每個機制都有單獨教學、鞏固與逐步結合舊規則的階段；同章的不同新機制不能在同一教學關突然同時引入。
4. 第一章以基礎和小型組合幾何為主，沒有密集玫瑰窗等突兀難度跳躍。
5. 每關有至少一條滿足全部條件的完整解法。
6. 錯誤 START 被阻擋；普通線與紅線次數正確；箭頭逆向被阻擋；機關觸發和撤回還原正確。
7. 提示與通關判定遵守相同規則，不能僅憑畫面變色或邊數判定成功。
8. 沒有無功能直線節點、隱藏重疊線、穿過圓點的長線或未標示的交叉歧義。
9. 不只測試完美圓心路徑，也檢查手機尺寸、圓角回拖、快速拖曳、連續撤回和錯誤操作回復。
10. 對解鎖、章末、全關完成、音效關閉與存檔相容進行檢查。
11. 解法／程式測試通過不等於關卡有趣；仍需人工試玩評估路線取捨、造型與疲勞感。

## 11 執行、生成與驗證

需要 Python 3，在倉庫根目錄執行：

```sh
python3 -m http.server 8080 --directory dist
```

瀏覽器開啟 http://localhost:8080 。靜態部署使用 `dist/`，無需安裝依賴或建置。生成器與自動驗證另需 Node.js。

```text
dist/
  index.html          # 繁中卡比掌機、選關、設定與通關畫面
  style.css           # 響應式布局與機關標記
  game.js             # 觸控、提示、撤回、進度保存
  mechanics.js        # 共用的純狀態規則引擎
  levels.js           # 200 關與已驗證解法
generate-levels.cjs    # 決定性生成器與教學配置
geometry-atlas.cjs     # 幾何造型原始線段
build-atlas.cjs        # 真實交會節點與線段整理
verify.cjs            # 拖曳、撤回、提示與存檔測試
verify-mechanics.cjs   # 機關正向與錯誤操作測試
verify-geometry.cjs    # 幾何、重複配置與完整解法檢查
verify-progression.cjs # 章節、首次教學與前期可讀性檢查
```

重新生成及驗證：

```sh
node generate-levels.cjs
node verify-mechanics.cjs
node verify-geometry.cjs
node verify-progression.cjs
node verify.cjs
BOARD_WIDTH=260 node verify.cjs
INPUT_TYPE=mouse node verify.cjs
```

目前驗證涵蓋 200 關完整解法、200 關拖曳完成與完整狀態撤回、小尺寸輸入、錯誤 START、方向／鎖／色彩／檢查點阻擋、提示生命週期、鬆手與存檔遷移。瀏覽器人工檢查包含掌機排版、特殊符號與提示演示；尚不代表 200 關均已完成人工趣味評估。

同一網站來源可讀取原始 `one-line-v1` 或舊 Demo 的 `kirby-line-demo-v1` 紀錄，保留完成關卡編號對應的解鎖資格與設定，備份舊紀錄並轉為 `dream-v3` 穩定 ID。不同網址的瀏覽器儲存互相隔離，不宣稱跨來源或跨裝置同步。
